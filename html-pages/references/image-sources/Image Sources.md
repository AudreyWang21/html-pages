# Image sources

> Dated hints from one round of testing, not guarantees: sites change their walls, keys and endpoints, so re-verify before relying on a row.

Image sources tested for agent access on 2026-10-08 from one Windows laptop (curl, no API keys unless stated): can an agent search, read the licence, and download a real image? The facts are dated hints, so re-verify before relying on one. When a page agent finds a source that works or breaks, add or update its row. Recipes live in the linked site files.

Every download needs a `file` or size check: several sources answer a failed request with a small HTML page that looks like a download (sometimes even with HTTP 200). Send a User-Agent that names the project, never an email. Exception: fws.gov (Akamai) 403s custom User-Agents but accepts curl's default, which identifies nothing.

**Microscopy gap.** None of the public-domain nature libraries had Daphnia or Paramecium. Atlas of Living Australia had a few Daphnia photos (15 CC BY). Microscopy routes: Zenodo / Plazi figures, Cell Image Library, PMC figures, Commons, and CDC PHIL for pathogens (it had no Daphnia or Paramecium).

Blocked and retired sources (bot walls, missing keys, dead sites) are in [Image Sources (Blocked)](Image%20Sources%20%28Blocked%29.md), so the next agent can skip the detour.

**Regions.** Outside Japan, national portals in Asia, Africa and Latin America mostly weren't agent-friendly; the aggregators (Commons, Europeana, Smithsonian, Wellcome, Cleveland) are the realistic route.
